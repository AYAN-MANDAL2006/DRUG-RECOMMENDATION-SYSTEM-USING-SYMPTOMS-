How It Works: System Architecture & Pipeline

An 8-stage pipeline converting natural language symptom input into transparent educational medicine information.

STAGE 1

Natural Language Symptom Input

The user enters symptoms in plain free-form English (e.g., "I have fever, headache and body pain").

STAGE 2

NLP Text Preprocessing

Applies lowercasing, punctuation stripping, tokenization, and removes non-informative English stopwords.

STAGE 3

Symptom Normalization & Synonym Mapping

Maps informal terms to canonical database symptoms (e.g., "head ache" → "headache", "high temp" → "fever").

STAGE 4

TF-IDF & Naive Bayes Symptom Matching

Matches extracted feature tokens against dataset health conditions to calculate transparent similarity scores (e.g., Match Score: 0.85).

STAGE 5

SQLite Relational Database Lookup

Queries normalized tables (symptoms, conditions, condition_symptoms, medicines) via parameterized SQL queries.

STAGE 6

Educational Medicine Information Retrieval

Fetches associated OTC medicine profiles including generic name, category, common use, precautions, and side effects.

STAGE 7

Safety & Emergency Rule Evaluation

Screens input for red-flag emergency keywords (e.g., chest pain, breathlessness). If detected, triggers immediate emergency care warnings and withholds medicine suggestions.

STAGE 8

Professional Consultation Guidance

Presents structured educational report accompanied by mandatory disclaimers advising direct clinical consultation with a healthcare professional.
